# Архитектура

## Раскладка папок

```
NORMA/
├─ NORMA.bat            запуск: права администратора, затем app\norma.ps1
├─ tests\               золотые файлы для сверки C# и эталона
├─ VERSION              номер версии (0.X), единственный источник
├─ LICENSE              MIT, код NORMA
├─ THIRD_PARTY_NOTICES.md  авторство, лицензии и контрольные суммы чужих компонентов
├─ app\                 код NORMA
│  ├─ norma.ps1         меню и точка входа (в фоне: NORMA_MODE=background)
│  ├─ core\             ядро (см. ниже)
│  └─ native\           собственный движок (C#, эксперимент) и его скрипты
├─ strategies\          стратегии: norma\ (создаются генератором), user\ (ваши)
├─ vendor\zapret\       оригинальный zapret-discord-youtube, файлы не менять
├─ data\                то, что создаёт работа: state.json, settings.json, ranking.json, logs\, backup\, background-status.json, norma.pid
├─ docs\                документация (OPTIONS.md создаётся генератором)
├─ .github\             CI, релизы, шаблоны обращений
└─ tools\               инструменты разработчика: gen_strategies.py, selftest.ps1
```

Правило: всё чужое лежит в `vendor\`, всё своё в `app\` и `strategies\`, всё созданное работой в `data\`.
Поэтому обновить upstream значит заменить одну папку, а удалить следы NORMA значит удалить `data\`.

## Модули ядра (app\core)

| Файл | Отвечает за |
|---|---|
| `lib.ps1` | пути, журнал (`Say`, `Save-NormaLog`), состояние и память по сетям, загрузка стратегий (три источника), запуск и остановка `winws`, проверка сайтов через `curl.exe`, защита «winws умирает вместе с окном» (Job Object) |
| `model.ps1` | модель стратегии: разбор аргументов `winws` на профили и параметры, описание, ключ эквивалентности, справочник `options.txt` |
| `plan.ps1`, `native/NormaPlan.cs` | планировщик приёмов: какие пакеты отправит стратегия на образце ClientHello (см. [ENGINE.md](ENGINE.md)) |
| `settings.ps1` | настройки пользователя (`data/settings.json`) и экран «Настройки» |
| `selfupdate.ps1` | обновление самой NORMA (проверка релиза, скачивание, проверки, замена папок с откатом) и плановое обслуживание фонового режима |
| `updates.ps1` | версии (NORMA и оригинал), транзакционное обновление файлов, списки доменов, режимы и обновление IPSet |
| `autopick.ps1` | `Invoke-AutoPick`: замер без обхода, перебор стратегий, бенчмарк (три прогона, медиана времени) |
| `session.ps1` | `Invoke-Session`: рабочая сессия; `Watch-Session`: сторож (здоровье сайтов, смена сети), фоновый режим |
| `doctor.ps1` | `Invoke-Doctor`: диагностика окружения |
| `autostart.ps1` | задача планировщика, запуск и остановка фонового режима |

Модули подключаются из `norma.ps1` через dot-source, поэтому все функции общие.

## Как идёт работа (пункт «Включить»)

1. `Invoke-Session` проверяет окружение, снимает конфликты (старые winws, служба zapret).
2. Определяет подпись сети (имя подключения + шлюз) и берёт стратегию, которая работала в этой сети; иначе последнюю рабочую.
3. `Invoke-AutoPick`: замер без обхода делит проверки на «заблокировано» (нужно открыть) и «открывается» (контроль, не ломать).
   Для каждой стратегии: запустить `winws`, подождать, проверить сайты. Побеждает первая, которая открывает всё нужное и не ломает контроль.
4. `Watch-Session` раз в 45 секунд проверяет смену сети и доступность нужных сайтов; при деградации подбирает другую стратегию.
5. При выходе `winws` останавливается, журнал сохраняется в `data\logs`.

## Соглашения для кода

- Windows PowerShell 5.1: без `?.`, `??`, тернарных операторов и других возможностей PowerShell 7.
- Файлы `.ps1` в UTF-8 с BOM (кириллица). Скрипты читаются как UTF-8 явно (см. `NORMA.bat`).
- Функции вывода только через `Say` (пишет на экран и в журнал). Возвращаемые значения функций не должны смешиваться с выводом: лишний вывод в конвейер превращает результат в массив.
- Не переименовывать переменную `$profile` (автоматическая в PowerShell): в коде используется `$prof`.
- Прежде чем коммитить: `powershell -File tools\selftest.ps1`.

## Собственный движок

`app\native\NormaLab.cs` реализует перехват через WinDivert (fake + disorder, сборка большого ClientHello).
Он экспериментальный и запускается из меню «Дополнительно»; основной обход делает `winws`.

## Бенчмарк

`Invoke-AutoPick -Benchmark` пробует все стратегии. Годная стратегия проверяется трижды: результат берётся по худшему из прогонов
(стабильность) и медианному времени ответа.
`Sort-StrategyRows` упорядочивает результаты: больше открытых сайтов лучше, затем меньше время ответа; результаты в пределах 15% считаются равными
и идут в порядке перебора, чтобы шум измерения не выдавался за преимущество. Итог сохраняется в `data/ranking.json`.

## Аккуратность работы с системой

- **Процессы.** Свой `winws` NORMA останавливает по удерживаемому объекту процесса. В `data/winws.pid` для каждого запуска записаны владелец (pid и время запуска экземпляра NORMA)
  и сам `winws` (pid, время запуска, путь к файлу). Остатки завершённого экземпляра опознаются по всем этим признакам: имени, времени запуска и пути; если что-то не совпало
  или не читается, процесс не трогается. Чужие `winws` и `goodbyedpi` не завершаются без согласия; в фоновом режиме при конфликте запуск отменяется.
- **Очистка.** Выгрузка драйвера WinDivert и возврат TCP timestamps выполняются, только если нет работающего фонового NORMA и других окон NORMA. Фоновый останавливается с согласия пользователя.
- **TCP timestamps.** Исходное значение запоминается в `state.json` и возвращается при выходе, при остановке фонового режима и в пункте «Очистка». Если исходное состояние определить нельзя, настройка не меняется.
- **Ответы сайтов.** `Test-UrlsDetailed` возвращает код и класс ответа (нет ответа, 2xx, 3xx, 4xx, 5xx). «Открывается» значит «получен настоящий ответ»:
  сертификат проверяется, поэтому ответ нельзя подделать, а 404 корня сервиса не считается блокировкой.
- **Файлы.** Контрольные суммы `vendor/zapret/bin` проверяются Доктором по манифесту `app/core/checksums.txt`. Обновления идут через `Invoke-FileUpdate`:
  скачать и проверить всё (для IPSet строго по формату адресов), затем заменить с резервной копией в `data/backup` (хранится 10 последних), проверить запись и при сбое откатить с проверкой отката.

## Автозапуск и фоновый режим

Задача планировщика «NORMA» запускает `app/background.ps1` при входе пользователя (с задержкой 30 секунд, с высшими правами, с перезапуском при сбое).
Тот загружает `app/norma.ps1` в режиме `background`: подбор, сторож, плановое обслуживание каждые 30 минут. Состояние пишется в `data/background-status.json`,
журнал в `data/logs/norma-background-*.log`. `data/norma.pid` хранит pid и время запуска (формат «pid|время»); старый формат только с pid не принимается, а перед остановкой дополнительно проверяется командная строка процесса.
Работающие экземпляры регистрируются в `data/instances.txt` (pid, время запуска, вид).

## Автообновление

Фоновый режим раз в `updateCheckHours` часов (по умолчанию 24) обновляет списки (если включено) и проверяет релиз на GitHub. Установка (`Install-NormaUpdate`) идёт по шагам,
и любой неудачный шаг оставляет установленную версию нетронутой:

1. замок движка (см. ниже) получен, и нет помех: других работающих экземпляров NORMA (реестр `data/instances.txt`, записи владельцев `winws`, pid-файл фонового режима; свой процесс не считается) и чужих `winws`;
2. релиз стабильный, новее установленной версии, в нём есть архив и файл `.sha256`;
3. архив скачан и сверен с SHA-256; распакован безопасно (имена с `..` отвергаются);
4. проверены структура пакета, версия и контрольные суммы `bin` по манифесту внутри пакета;
5. из нового пакета запущена самопроверка (`tools/selftest.ps1`) на этом компьютере;
6. помехи проверены ещё раз непосредственно перед действием (замок удерживается, состояние не изменится); остановлен обход, выгружен драйвер WinDivert (иначе его файл занят), перенесены пользовательские списки и режим IPSet;
7. папки заменены переименованием (`Invoke-TreeSwap`): старые уходят в `data/backup/selfupdate-...`; при сбое откат с проверкой результата;
8. фоновый процесс запускает свою замену (`-WaitPid`) и завершается; интерактивное окно просит перезапустить NORMA.bat.

`NORMA.bat` не заменяется, пока окно запущено из него (cmd читает batch-файл по смещению), поэтому его менять в релизах нужно редко.

## Замок движка и реестры

Драйвер WinDivert один на машину, поэтому работать с движком одновременно может только один экземпляр NORMA. Гарантию даёт **замок движка**: именованный мьютекс
`Global\NORMA-Engine-Lease` (`Enter-EngineLease`, `Exit-EngineLease`). Его получает один владелец атомарно, поэтому проверка «нет других экземпляров» и занятие движка
не разделены окном, в которое мог бы вклиниться второй запуск. Если владелец завершился, в том числе аварийно, система освобождает замок сама.
Замок удерживают на всё время работы с движком: `Invoke-Session` (в фоне с ожиданием до 30 секунд, чтобы перезапуск после обновления дождался прежнего владельца),
`Install-NormaUpdate` и очистка. Повторное получение тем же процессом допускается (счётчик), чтобы вложенные операции не блокировали сами себя.

`data/instances.txt` и `data/winws.pid` остаются справочниками для сообщений и дополнительных проверок (в том числе для процессов более старых версий без замка).
Их чтение, изменение и запись выполняются под короткой блокировкой (`Invoke-RegistryLocked`), чтобы одновременные записи не теряли друг друга.
Самопроверка запускает настоящие процессы PowerShell: четыре одновременных запуска получают замок ровно в одном экземпляре, брошенный замок переходит дальше, четыре одновременные регистрации не теряют записей.
